# Утренняя сводка (Тип B: последовательность действий)

Запускается по просьбам вида «утренняя сводка», «что там на сегодня»,
«брифинг», «доброе утро». Четыре шага, строго по порядку, по одному вызову
инструмента за шаг.

**Шаги 1–3 — это команды, которые надо выполнить инструментом `exec`.**
Ни дату, ни погоду, ни дела ты не знаешь заранее: без вызова у тебя нет
этих данных. Шаблон из шага 4 заполняется только тем, что вернули команды.

## Шаг 1. Дата и время

```
date "+%A, %d %B %Y, %H:%M"
```

Нужно, чтобы отобрать дела именно на сегодня: своей датой ты не располагаешь.

## Шаг 2. Погода

```
curl -s "https://wttr.in/Minsk?0&T&M&lang=ru"
```

Подробности про параметры — в скилле `weather-cli`. Город по умолчанию Минск;
если пользователь назвал другой — подставь его.

## Шаг 3. Дела на день

Пропускать этот шаг нельзя: пока ты не прочитал файл, ты не знаешь,
есть ли сегодня дела, и написать «дел нет» не имеешь права.
Сначала локальный файл — он есть всегда:

```
cat data/agenda.md
```

Если файла нет (`exit code: 1`), проверь, установлен ли CLI календаря/почты:

```
command -v gog >/dev/null && gog calendar today || echo "gog не установлен"
```

Нет ни файла, ни `gog` — так и скажи в сводке: «список дел недоступен».
Не выдумывай встречи.

Из файла бери только строки с сегодняшней датой из шага 1. Строки прошедших
дней в сводку не идут.

## Шаг 4. Итог

Только когда шаги 1–3 выполнены и их результаты у тебя перед глазами,
собери всё в одно сообщение — без вызовов инструментов и без заготовок
в угловых скобках. В сообщении должно быть ровно четыре части:

1. Приветствие с днём недели и датой из шага 1.
2. Одна строка о погоде из шага 2: температура, ощущается, осадки, ветер —
   и практический совет (зонт, тёплая куртка, ничего особенного).
3. Список дел из шага 3 маркерами «• время — дело». Файл пустой или
   недоступен — так и напиши одной строкой.
4. Одна короткая строка: на что сегодня обратить внимание.

Пиши живым языком, как человек человеку. Никаких плейсхолдеров, скобок
и пометок вроде «(вставить сюда)» в готовом сообщении быть не должно.

## Правила

- Шаги выполняются все и по порядку: 1 → 2 → 3 → 4. Ни один не пропускается.
- Не более одного вызова инструмента за шаг: сначала результат, потом решение.
- Шаг провалился — не бросай сводку: отметь этот пункт как недоступный
  и доделай остальные.
- Всего 4 шага. Если после них данных не хватает — отвечай тем, что собрал.
- Не показывай пользователю сырой вывод команд и не пересказывай ASCII-картинки.
