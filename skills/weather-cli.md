# Погода через wttr.in (Тип A: инструкция к CLI/API)

Сервис `wttr.in` отдаёт погоду обычным HTTP-запросом. Никаких ключей и
регистрации не нужно — только `curl` через инструмент `exec`.

## Базовое правило

Всегда добавляй `-s` (тихий режим) и явно проси текстовый формат, иначе
сервис отдаст ANSI-раскраску и рамки, которые в Telegram превратятся в мусор.

```
curl -s "https://wttr.in/Minsk?0&T&M&lang=ru"
```

## Параметры запроса

| Параметр | Что делает |
|---|---|
| `?0` | только текущая погода, без прогноза (самый короткий ответ) |
| `?1` | текущая + прогноз на 1 день |
| `?2` | текущая + прогноз на 2 дня |
| `T` | без ANSI-цветов — обязательно для Telegram |
| `M` | ветер в м/с, а не в км/ч |
| `lang=ru` | описание погоды по-русски |
| `format=3` | одна строка: `Minsk: ⛅️ +17°C` |
| `format=4` | одна строка с ветром и влажностью |

Город пишется прямо в пути: `https://wttr.in/Berlin`. Названия из двух слов —
через `+`: `https://wttr.in/New+York`. Кириллица работает, но латиница надёжнее.

## Что выбрать

- Нужна одна строка для сводки → `curl -s "https://wttr.in/Minsk?format=4&lang=ru"`
- Нужны подробности на сегодня → `curl -s "https://wttr.in/Minsk?0&T&M&lang=ru"`
- Нужен прогноз на завтра → `curl -s "https://wttr.in/Minsk?1&T&M&lang=ru"`
- Нужны данные для расчётов → `curl -s "https://wttr.in/Minsk?format=j1"` (JSON;
  большой, поэтому сразу режь нужное: `... | head -c 2000`)

## Разбор ответа

Ответ — готовый текст, пересказывай его своими словами и коротко. Из блока
`?0` бери температуру, ощущается-как, осадки и ветер. Остальное пользователю
обычно не нужно.

## Если не получилось

- `exit code: 6` или `Could not resolve host` — нет сети. Скажи об этом прямо,
  не выдумывай погоду.
- В ответе `Unknown location` — город не распознан, попробуй латиницей.
- Пустой ответ или HTTP 503 — сервис перегружен, повтори **один** раз,
  дальше честно сообщи, что погода недоступна.

Никогда не придумывай числа: если `curl` не отработал, погоды у тебя нет.
