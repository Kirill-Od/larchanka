# Погода через wttr.in (Тип A: инструкция к CLI/API)

Сервис `wttr.in` отдаёт погоду обычным HTTP-запросом. Никаких ключей и
регистрации не нужно — только `curl` через инструмент `exec`.

## Команда

Одна на все случаи, выполняй её как есть:

```
curl -s "https://wttr.in/Antalya?0&T&M&lang=ru"
```

Каждый флаг обязателен: `-s` глушит служебный вывод curl, `T` убирает
ANSI-раскраску (без него в Telegram приезжают рамки и мусор), `M` даёт ветер
в м/с вместо км/ч, `lang=ru` — описание по-русски.

Больше одного запроса на задачу не нужно: погода за минуту не меняется.

## Что в адресе можно поменять

Город пишется прямо в пути — вместо `Antalya` подставь нужный. Названия из двух
слов соединяются плюсом (`New+York`). Кириллица работает, но латиница надёжнее.

Остальное меняется только если задача прямо этого требует:

- `?0` — текущая погода. Нужен прогноз: `?1` даёт день, `?2` — два дня.
- `?format=4` вместо `?0&T&M` — одна строка вместо блока, годится для сводки.
- `?format=j1` — JSON для расчётов. Ответ большой, сразу режь: `| head -c 2000`.

## Разбор ответа

Ответ — готовый текст, пересказывай его своими словами и коротко. Из блока
`?0` бери температуру, ощущается-как, осадки и ветер. Остальное пользователю
обычно не нужно.

## Если не получилось

- `exit code: 6` или `Could not resolve host` — нет сети. Скажи об этом прямо,
  не выдумывай погоду.
- В ответе `Unknown location` — город не распознан, попробуй латиницей.
- Пустой ответ или HTTP 503 — сервис перегружен, повтори **один** раз,
  дальше честно сообщи, что погода недоступна.

Никогда не придумывай числа: если `curl` не отработал, погоды у тебя нет.
